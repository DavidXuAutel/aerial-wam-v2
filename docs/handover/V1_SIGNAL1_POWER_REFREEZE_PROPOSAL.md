## 1. 已测事实（08-15 严谨 ①；须写入活文档，非新实验）

权威跑：`v1_partial_1_r60_20260815` / merge `v1_gate_r60_20260815.json`。

| 项 | 值 |
|---|---|
| hard coll | v0=**0.75** → v1=**0.50** |
| target | ≤ `0.8×v0` = **0.60**（δ=0.20） |

| 对 target 的率裕度 | 0.60−0.50 = **0.10** → **0.8 局**（`0.10×8`） |

## 2. 条款② — 配对强制（待签字）

**意图**：禁止只报边际 `coll_rate` 均值差；权威主张必须建立在**同 starts 配对**上。

| 项 | 草案（签字填数） |
|---|---|
| **配对** | V0 臂与 V1 臂 **同一 accepted start 集**；逐 ep 记 `(coll_v0, coll_v1)` |
| **必报** | 列联表：`n00,n01,n10,n11`；discordant `b=n10`（仅 V0 撞）、`c=n01`（仅 V1 撞） |
| **功效判据（待填）** | 精确二项 / McNemar 对 `H0: b=c`；**authoritative** 须 `p < α` **或** `min(b+c) ≥ k`（二者取签字值） |
| **α / k（待签）** | `α = ___`（建议起点 0.05，n=8 下极苛刻）· `k = ___`（建议起点 3） |
| **未满足时** | `power_ok=false`；① 可仍 `delta_ok`（率条件），但 **merge 标 `fragile` / 非全权 auth**——具体门闩：签字二选一：**(A)** 拒 merge，或 **(B)** merge 允许但 JSON/`V1_GATE_STATUS` 强制 `fragile=true` |

## 3. 条款③ — 裕度带（待签字）

**意图**：过 `≤ target` 不够；权威主张须留**可判定裕度**，避免 0.8 局擦边。

| 项 | 草案（签字填数） |
|---|---|
| **率条件（不变）** | 仍要 `v0>0` 且 `v1 ≤ (1−δ)·v0`（δ=0.20 已钉） |
| **裕度带（新增）** | 另须 `target − v1 ≥ m` **或** `(target − v1)·n ≥ e_min` |
| **m / e_min（待签）** | `m = ___`（率）· `e_min = ___`（局；建议起点 **2.0** 局，则现跑 0.8 局 → 不满足） |
| **未满足时** | `margin_ok=false`；处置同条款②的 (A)/(B) |

**现跑对照**：`e = 0.8 < 2`（若采纳建议）→ 条款③会把 08-15 标为 **fragile / 非全权**，**不**改写当时 PASS 文书。
