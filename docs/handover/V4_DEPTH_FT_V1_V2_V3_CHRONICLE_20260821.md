## 3. v3 FAIL 归因

### 3.1 一句话

v3 修好了 **⓪c**（真 pinball + 关 AbsRel/SILog），并把 ⓪d **rate** 压到全库点估计 ≤0.05；但**主表**仍因 miss&gt;0.05，且全库/主表 **consec≥2** 合取失败。根因是 **A″ 在训练集上几乎无梯度（hinge≈0）却触发早停**，而 **consec 本就不在单帧 loss 的能力边界内**。

### 3.4 因果链（按强度）

1. **A″ 假饱和（直接）**  
   缓存保证 `n_fwd=8`，但 softmin forward_min 在这批难例上已几乎不过 trigger（hinge≈0）。早停按声明触发 → 有效训练窗口很短，主导是 B″。Miss 帧（D̂&gt;3 且 GT≤3）在缓存分布里稀少或被 softmin 抹平，A″ 几乎没推 ⓪d。

2. **B″ 成功但域偏前向（解释 ⓪c）**  
   前向 crop ∩ 近带 AbsRel pinball：主表 p90 0.74→0.43、全库 0.72→0.40。`(0,1.5]` 仍差（主表分箱 p90≈1.33）但总 p90 过线 ⇒ 「关全图回归 + 真尾权」对 ⓪c 对症。

3. **consec 超出单帧 loss（预期内拦路）**  
   老头已 consec=2；v3 rate 改善时 consec 升到 3。声明不做滞回/时序 ⇒ 即便 rate≤0.05 合取仍 FAIL。这是能力边界，不是实现 bug。

4. **主表分母薄（加重 rate 腿）**  
   `n_fwd=35`：miss≈3/35≈0.086。全库 4/106≈0.038。同一头在更大样本上 rate 过线，主表仍不过 → 小 holdout 噪声 + 分布差；权威仍按声明用主表。

### 6.3 §3.4 归因：结论对，但机制写错一处

- **「miss 帧被 softmin 抹平」与 softmin 的符号方向矛盾**：soft-min **≥** true min（温度越大越靠均值、值越**大**），而过读 hinge 是 `relu(D̂_fwd − GT_fwd/trigger)` ⇒ softmin 只会**放大**该 hinge，不可能把它归零。**「96% 步 `fwd_hinge=0`」本身就是异常信号**，指向的是 **缓存选择准则 ≠ miss 条件**：缓存按「窗内 `GT_fwd ≤ trigger` 帧数 ≥ K=4」选难例，而 miss 条件是 `GT_fwd ≤ 3` **且** `D̂_fwd > 3` ⇒ **训练集里几乎不含要治的失败模式**。§4-1 的修法正是这个，故**结论对、机制错**。**须删掉 softmin 那半句**，否则 v4 会去调温度（错的旋钮）。
- **「假饱和」应改称「选择性偏差 / 训练信号缺失」** —— 它不是收敛现象。命名直接决定 v4 修哪儿（早停阈值 ✗ / 采样 ✓）。
